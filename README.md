# Activity Checker

Локальная коллекция событий, мест, сообществ и организаторов. Начальная география — Белград и Сербия. Две страницы: **Активности** и **Источники**. Один пользователь, без аккаунтов, фонового обхода сайтов и встроенного LLM.

## Запуск

Нужен **Node.js 24+**. Проект создан в этой директории, без вложенной копии и без инициализации Git.

```sh
npm ci
npm run dev
```

Откройте **http://127.0.0.1:4318**. Один процесс обслуживает API и React. Изменения фронтенда обновляются через Vite; после изменения backend нужен перезапуск. Для обычного использования:

```sh
npm run build
npm start
```

При запуске через Life Hub открытая вкладка отправляет локальный heartbeat. После закрытия всех вкладок Life Hub может остановить сервис по `.runtime/web.pid` согласно политике `stopWhenBrowserIdle`.

Сервер слушает только `127.0.0.1`. Остановка — `Ctrl+C`. `PORT` и `ACTIVITY_DB` можно задать в `.env.local`; эти две настройки требуют перезапуска. В стандартной структуре `life-stack` SQLite находится в `../data/activity-checker/activity.sqlite`. SQL-миграции и рекомендованный каталог источников применяются при запуске. Отдельная команда: `npm run db:migrate`.

Первая пустая база содержит четыре **вымышленных demo-записи**. Кнопка «Убрать примеры» удаляет их. При следующих запусках примеры не возвращаются. Демо не объединяются с реальными данными.

## Первое использование

1. Откройте **Источники → OpenStreetMap**. Он включён и не требует ключа.
2. Запустите **Синхронизировать**. Найденные POI появятся в **Активностях → Места**. Кнопка «Проверить» отдельно проверяет API без записи активностей.
3. У каждого источника **Настроить** открывает географию, URL, состояние и инструкции. Нажатие на название раскрывает краткий setup, состояние ключей, последний результат и документацию.
4. Для внешнего исследования откройте **Импорт JSON → Промпт для чата**. Вставьте результат, проверьте предпросмотр, затем импортируйте.
5. В карточке доступны оригиналы и raw payload, заметка, избранное, редактирование, архив, связи и ручное объединение.

Переключатель **Serbia** показывает все записи страны, **Belgrade** — город. Источник имеет собственную географию; её можно изменить в настройках или создать второй источник того же провайдера. «Синхронизировать включённые» запускает только подходящие текущему scope источники. Источники уровня страны видны в scope Serbia; они не маскируются под городские.

Для событий есть сегодня / неделя / выходные / период; даты сравниваются в `Europe/Belgrade`. События без подтверждённой даты не попадают в временные фильтры. Прошедшие события помечаются «прошло», автоматически не архивируются. Сообщества по умолчанию сортируются RU → international → local. «Активные» означает неархивные записи, а не подтверждение актуальности события.

Ключи для заготовки **не делают её рабочим подключением**. Даже при заполненных переменных Test / Sync недоступны, пока не реализован адаптер. Неуспешный запрос, отсутствие разметки или credentials не имитируются пустым успешным импортом. У Ticketmaster пустой ответ допустим и означает отсутствие найденных событий.

Плашка **«Регистрация»** отмечает 11 провайдеров, для API которых требуется аккаунт: в раскрытой инструкции есть ссылка и название сервиса (например, Apify, а не Instagram). Плашка описывает требование подключения; наличие аккаунта не означает, что адаптер уже реализован. Публичные афиши и Overpass обходятся без аккаунта.

```sh
cp .env.example .env.local
```

Заполните нужные поля. **Ключи провайдеров перечитываются при запросах без перезапуска**. Нажмите «Обновить статусы» на странице источников, затем «Проверить»; системные переменные окружения имеют приоритет над файлом. UI получает только признаки наличия ключей. Ключи не сохраняются в SQLite или браузере. URL источника с `token`, `apikey`, `key` и подобными параметрами запрещены; такой источник должен использовать отдельную серверную credential-настройку.

Ссылки и последовательность получения credentials находятся в **Источники → Настроить**, а также в [справочнике провайдеров](docs/PROVIDERS.md). Необязательные платные API не вызываются, пока вы сами не настроите и не запустите их.

## Pipeline и хранение

```text
Source → provider.sync → RawItem → provider.normalize → validation
       → deterministic matching → Entity + EntitySourceLink → UI
                                  ↘ SourceCandidate
```

SQLite работает через встроенный `node:sqlite`, без ORM и отдельного процесса БД. Все четыре canonical-типа используют общую таблицу `entities` с полем `type`, индексируемыми географией/датой и валидированным JSON остальных полей. Связи вынесены в `entity_relations`. Это упрощает unified view, миграции и импорт, сохраняя типы в TypeScript/Zod.

- `scopes`: страны/города, timezone и OSM area ID.
- `sources`: настройки источника, состояние, последний запрос и результат; без secrets.
- `source_items`: original payload/text, external ID, URL, checksum, даты. Изменённая версия сохраняется отдельно; повтор той же версии обновляет `fetchedAt`.
- `source_item_heads`: текущая версия каждой исходной записи; позволяет отличать повторный ответ от возврата источника к старой версии.
- `entity_source_links`: все источники каждой записи.
- `entity_keys`: детерминированные признаки идентичности.
- `duplicate_pairs`: сомнительные совпадения; автоматического destructive merge нет.
- `source_candidates`: найденные ссылки с исходной записью и состоянием new/accepted/ignored.
- `sync_runs`: результаты ручных синхронизаций, включая ошибки.

Нормализация объединяет варианты Beograd / Београд / Белград в Belgrade, приводит ISO timestamps к UTC, убирает tracking-параметры из ключей URL. Другие query-параметры, например ID билета, сохраняются.

Сопоставление: provider external ID, известные IDs, подходящий canonical URL, затем полные признаки события (название + время + площадка) или места (название + адрес/координаты). Одинакового названия недостаточно. GUID разных RSS-лент не считаются одинаковыми. Возможные дубли показываются в карточке и фильтре. При ручном объединении сохраняются поля выбранной карточки, provenance, заметки и связи; вторая canonical-запись удаляется.

Ручные изменения полей защищены `overrides` и не затираются дальнейшим Sync. Избранное, архив, заметки и AI metadata сохраняются. Исчезновение записи из внешнего источника не удаляет её. Новые ссылки создают кандидатов, но не запускают обход или подключение автоматически.

## JSON-импорт и внешняя AI-обработка

Пример: [examples/import.json](examples/import.json). Машиночитаемая схема: [docs/import.schema.json](docs/import.schema.json), актуальная runtime-версия — `GET /api/import/schema`. Допустим массив, объект `{ "version": 1, "entities": [...] }` или JSON внутри Markdown fence. До 1 000 записей и 5 МБ за запрос.

Обязательные поля: `type` и `title`. Типы: `Event`, `Place`, `Community`, `Organizer`. Неизвестные поля отклоняются. По умолчанию country=`RS`, city=`Belgrade`; для другой географии указывайте их явно. Даты: `YYYY-MM-DD` либо ISO 8601 с `Z`/offset. Date-only не превращается в выдуманное время. `url` — оригинал конкретной записи, `website` — сайт организации. Неизвестные значения лучше пропускать.

```json
{
  "version": 1,
  "entities": [
    {
      "type": "Community",
      "title": "Подтверждённое название сообщества",
      "country": "RS",
      "city": "Belgrade",
      "url": "https://example.org/community",
      "languages": ["ru", "en"],
      "audience": "international",
      "tags": ["hiking"]
    }
  ]
}
```

Пакет валидируется целиком. Preview выполняет тот же pipeline в откатываемой транзакции; до кнопки «Импортировать» ничего не остаётся в БД. Сам импорт также атомарный.

AI-поля: `aiScore` (0–100/null), `aiDecision` (`unknown|recommended|hidden`), `aiReason`, `aiTags`, `aiProcessedAt`. Они хранятся в JSON `entities.data`. Встроенного LLM нет; внешний агент может работать через локальный API: получить карточку, изменить эти поля и отправить полный canonical input через `PUT /api/entities/:id`. Sync не перетирает внешнюю оценку. `hidden` — metadata; оно не скрывает записи автоматически без пользовательского фильтра. Экспорт JSON переносит canonical-поля, но не заменяет полный backup SQLite (не включает личные состояния, связи и raw-историю).

## Добавить провайдера или географию

Контракт: [server/providers/types.ts](server/providers/types.ts). Добавьте небольшой модуль с `defineProvider(info, { testConnection, sync, normalize })`, затем одну строку в [registry.ts](server/providers/registry.ts). UI автоматически использует его описание, credential keys, steps, docs и supported types. Инструкции и пример — [docs/PROVIDERS.md](docs/PROVIDERS.md).

Новый провайдер автоматически получает catalog Source при запуске. Существующие пользовательские настройки seed не перезаписывает. Для новых credential-полей добавьте имя в `server/secrets.ts` и `.env.example`. Не передавайте секреты через raw payload или URL источника.

Новая география добавляется миграцией в `scopes`: ISO country, nullable city, timezone, OSM area ID. UI построит переключатель из БД. Для Overpass area ID = `3600000000 + relation_id`. В начальном seed Belgrade — граница городского населённого пункта [relation 2728438](https://www.openstreetmap.org/relation/2728438), Serbia — [relation 1741311](https://www.openstreetmap.org/relation/1741311). Для расширения географии временные фильтры UI также нужно перевести с начального `Europe/Belgrade` на `scope.timezone`.

## Ограничения первой версии

- JSON-LD читает только указанную страницу, без browser rendering и переходов по pagination. Наличие адаптера афиши не гарантирует полного покрытия сайта.
- RSS `pubDate` — дата публикации, не дата события. События без отдельного event timestamp сохраняются без даты.
- Повторяющиеся ICS-события пропускаются с предупреждением; обычные ICS учитывают TZID. JSON-LD timestamps без timezone оставляются пустыми с предупреждением.
- Overpass — общественный сервис; timeout/429/неполный ответ отображаются как ошибка. Альтернативный публичный или свой endpoint задаётся в `OVERPASS_URL`. OSM может содержать устаревшие сведения; применяется [ODbL и attribution](https://www.openstreetmap.org/copyright).
- Не более одной сетевой операции одновременно. Повторный Sync одного провайдера — через 60 секунд; ограничения переживают перезапуск. Test не блокирует первый Sync. Автоматических повторов платных запросов нет.
- Нет map view, авторизации, cron, автоматического web crawler или LLM SDK.

## Проверка и резервная копия

```sh
npm run check
npm test
npm run build
npm run test:http
```

Unit-тесты используют SQLite in-memory, ответы API подменены. HTTP smoke-тест создаёт временную базу и не обращается к внешним сервисам. Покрыты повторный импорт, сохранение raw-версий и правок, сомнительные дубли, merge, откат preview/ошибочного пакета, discovery, OSM/JSON-LD/RSS/ICS, connection states, cooldown и отказ API.

Для backup остановите сервер и скопируйте `../data/activity-checker/activity.sqlite`. Во время работы используйте штатный SQLite backup, а не копирование одного файла: WAL может содержать незаписанные изменения. Секреты из `.env.local` храните отдельно.
