# Подключение рекомендаций

Читать только выбранный пользователем раздел. UI провайдера может измениться:
если путь отличается, проверить его официальную документацию. Не получать ключи
за пользователя и не выводить уже сохранённые значения.

## Telegram — чтение публичных каналов

1. Открыть [my.telegram.org](https://my.telegram.org), войти со своим Telegram-номером.
2. Выбрать **API development tools**, заполнить форму приложения: название,
   короткое имя и подходящую платформу. Получить `api_id` и `api_hash`.
3. Записать их в локальный файл: `TELEGRAM_API_ID=...` и `TELEGRAM_API_HASH=...`.
4. После переноса в `.env.local` выполнить `npm run telegram:setup` (uv, Python 3.12),
   затем пользователь сам выполняет `npm run telegram:auth` в терминале,
   вводит номер, код и при необходимости 2FA.
5. Проверить `npm run start:verify`: он выводит только статус авторизации,
   без account/телефона/полного worker output. Ошибки
   авторизации/FloodWait сообщать без повторных входов или обхода ограничений.

Установка uv: [официальная инструкция](https://docs.astral.sh/uv/getting-started/installation/).
Нужна пользовательская MTProto-сессия; bot token не подходит. Сессия по умолчанию
`../data/activity-checker/telegram/activity-checker.session` — личный файл входа,
его не пересылают коллеге. Авторизация не означает запуск сбора каналов.
[Официальная инструкция](https://core.telegram.org/api/obtaining_api_id).

## Apify — необязательный дополнительный сбор

1. Зарегистрироваться/войти в [Apify Console](https://console.apify.com).
2. Открыть **API & Integrations** и создать отдельный токен для Activity Checker.
3. Для выбранных Actors разрешить запуск и чтение результатов; проверить
   тариф Actor и доступный баланс. Не запускать Actor ради получения токена.
4. Записать `APIFY_TOKEN=...` в локальный файл; после переноса отметить
   «ключ настроен». Работоспособность подтверждается только штатной проверкой
   с известным бюджетом, а не наличием строки.

[API tokens и scoped permissions](https://docs.apify.com/integrations/api).
Токены одного Apify-аккаунта могут расходовать общий баланс; отдельный токен
не создаёт отдельную квоту. Setup не расходует paid Actors budget.

## Ticketmaster Discovery API — необязательный источник

1. Создать аккаунт в [Ticketmaster Developer Portal](https://developer.ticketmaster.com).
2. В разделе приложений создать приложение и открыть его API key / Consumer Key.
3. Записать `TICKETMASTER_API_KEY=...` в локальный файл.
4. После переноса ключа отметить «настроен». При реальном использовании проверить
   текущую квоту и доступность событий выбранного города штатным адаптером.

[Getting started](https://developer.ticketmaster.com/products-and-docs/apis/getting-started/).
Этот ключ не нужен для AllEvents, Afisha и локальных публичных сайтов.

## Без дополнительных ключей

Публичные агрегаторы и веб-страницы читаются существующими адаптерами; доступность,
403/CAPTCHA и renderer проверяются во время сбора. Hosted web search использует
возможности текущего агента, отдельный ключ OpenAI для Activity Checker не нужен.
Если поиск/renderer недоступен, обозначить пробел и продолжить доступные источники.

Код общих коннекторов и Knowledge берутся из соседнего Personal Radar checkout.
Удалённый Personal Radar MCP — отдельный, необязательный способ доступа:
использовать его собственную документацию, только если пользователь выбрал его,
не выдумывать endpoint/токен и не подменять им рабочую локальную сессию молча.
