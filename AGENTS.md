# Repository instructions

When this checkout is inside `life-stack`, first read the shared [workspace instructions](../AGENTS.md) if they have not already been loaded. This file supplies project-specific overrides. If the shared file is absent in a standalone clone, continue with this file.

- Communicate with the user in Russian unless they request another language.
- Preserve unrelated changes and never publish, delete, or rewrite data without an explicit request.
- The canonical repository is https://github.com/gavrevnik/activity-checker.
- The default branch is `master`.
- The live SQLite database is `../data/activity-checker/activity.sqlite` in the standard `life-stack` layout. `ACTIVITY_DB` may override it.
- Never use the live database in tests. Tests must use in-memory or temporary SQLite databases.
- Keep provider secrets only in the ignored `.env.local`; never include them in source, fixtures, logs, or chat output.
- Update `README.md` when setup, storage, providers, or user-visible behavior changes.
- Before handing off code changes, run `npm test`, `npm run check`, and the relevant focused verification.
- For profile-guided MCP discovery/enrichment (including "using MCP TG find new channels about …") and user-requested LLM sync/filter/review of ordinary aggregators such as Tickets.rs, use `ai-mcp-discovery` at `skills/ai-mcp-discovery/SKILL.md`. Refresh shared preference feedback and keyword-query memory before planning and after completed search batches. For quota-limited/paid providers, show available total/used/remaining quota and obtain a per-run spending limit before live calls; a previous run's budget is not authorization. Do not activate this workflow for a purely technical sync without LLM selection.
- For a personal activity digest by dates or topic (week/weekend plans, concerts, professional meetups), use `skills/digest/SKILL.md`: refresh each due aggregator, archive past events, incrementally monitor enabled Telegram channels, research current LLM Web sources, deduplicate and persist reviewed event scores before returning recommendations. A digest request authorizes these routine updates/imports; paid-provider budgets remain separate. Creating/editing the skill does not execute a digest.
- For Telegram channel discovery, use `activity-checker-telegram-discovery`: batch up to 30 useful hypotheses, start with non-mutating channel-name search, deduplicate all stored/hidden/excluded communities, then inspect description/size → current pins without date bounds → recent posts, and optionally expand from relevant seeds with recommendations. Set `store=true` only when the user asks to enrich Activity Checker. Global full-text post search is disabled; scoped `telegram_search_channel_messages` is available in discovery and monitoring. For posts from known channels, use `activity-checker-telegram-monitoring`, batch at most 20 channels, prefer date/message-ID bounds, and keep the conservative sequential delay. Never authorize Stars spending; stop on FloodWait or an authorization requirement.
- When forum topics help discovery, list them with `telegram_group_topics`, announce the closest topic and why, then read a bounded `telegram_topic_posts` sample. Use verified linked-chat/posts-comments tools only to answer a concrete research question (community interaction, participation/logistics); no auto-join/import. Discussion replies are intentionally included without changing feed settings; channel/keyword/ad exclusions remain active. See `docs/TELEGRAM_DISCOVERY.md`.
